# ตรวจรูปโพสต์โหลดไม่ได้ — 4 พฤศจิกายน 2026

## สิ่งที่ยืนยันได้

- รูปของโพสต์ตามภาพยังอยู่ใน Storage เป็น JPEG ขนาด 169,182 ไบต์ path ตรงกับข้อมูลโพสต์ และขนาดไม่เกินขีดจำกัด 10 MiB ของตัวโหลดรูป
- โพสต์เลือก `public` และทั้งสำเนา `authorIsPrivate` กับสถานะโปรไฟล์เป็นสาธารณะ
- ทดสอบด้วยบัญชีชั่วคราวที่ล็อกอินจริง: อ่านโพสต์ได้ HTTP 200 แต่ดาวน์โหลดรูปเดียวกันได้ HTTP 403 `Permission denied.` ลบบัญชีทดสอบสำเร็จแล้ว ไม่ได้แก้โพสต์หรือไฟล์รูป
- Rules ที่เผยแพร่ตรงกับไฟล์ก่อนแก้ สำรองไว้ที่ `build/media-validation/storage-before.rules`

## สาเหตุ

Storage Rules รอบแก้สิทธิ์ผู้ติดตามเริ่มตรวจ `followers/{viewer}` ก่อน จากนั้นผู้ชมที่ไม่ได้ติดตามต้องอ่านทั้งเอกสารโพสต์และโปรไฟล์เจ้าของ รวมสามเอกสาร แต่ Cloud Storage Rules จำกัด `firestore.get()`/`firestore.exists()` ที่สองครั้งต่อ request และอาจ cache การอ่านเอกสารเดิมได้ ดู [ข้อจำกัด Firebase Security Rules](https://firebase.google.com/docs/rules/rules-behavior)

จึงเกิดการปฏิเสธรูปของโพสต์สาธารณะ แม้สิทธิ์อ่านโพสต์ถูกต้อง การทดสอบ Emulator รอบก่อนผ่านเมทริกซ์การมองเห็นแต่ไม่พบข้อจำกัด production นี้

## การแก้

ปรับเฉพาะ [`storage.rules`](../storage.rules) ให้ตรวจทางสาธารณะก่อน (โพสต์ + โปรไฟล์ = สองเอกสาร) แล้วจึงตรวจทางผู้ติดตามเมื่อไม่ผ่านทางสาธารณะ คงเงื่อนไขโพสต์เฉพาะฉัน สถานะโปรไฟล์ และผู้ติดตามเดิมไว้ ไม่เปลี่ยนชื่อไฟล์ path สิทธิ์เขียน หรือข้อมูลโพสต์

ตรวจเมทริกซ์ Firestore/Storage ใน Emulator ผ่าน 118 เงื่อนไข ครอบคลุมบัญชีสาธารณะ/ส่วนตัว เจ้าของ ผู้ติดตาม คนทั่วไป คำขอที่ยังไม่อนุมัติ การถอนสิทธิ์ รูป วิดีโอ และโพสต์เฉพาะฉัน ผลอยู่ใน `build/media-validation/emulator-tests.log`

## สถานะ

**เผยแพร่และตรวจบน Firebase จริงสำเร็จแล้ว** หลังผู้ใช้อนุญาต อัปเดตเฉพาะ Storage Rules ของ `social-network-app-c22eb` ไม่มีการเปลี่ยน Firestore Rules, Functions, ไฟล์รูป หรือข้อมูลโพสต์ในรอบนี้

| ตรวจจริงด้วยบัญชีทดสอบ | ก่อนแก้ | หลังแก้ |
|---|---|---|
| อ่านโพสต์ | HTTP 200 | HTTP 200 |
| ดาวน์โหลดรูปเดิม | HTTP 403 | HTTP 200 |
| ไบต์รูป JPEG | อ่านไม่ได้ | 169,182 ไบต์ ครบตามไฟล์ใน Storage |
| ลบบัญชีทดสอบ | สำเร็จ | สำเร็จ |

ตรวจหลังแก้วันที่ 4 พฤศจิกายน 2026 เวลา 09:06 น. (Asia/Bangkok) รูปเป็น `image/jpeg` และมี JPEG signature ถูกต้อง SHA-256 ของไบต์รูปคือ `c3a913001c20c393818667916f80fa2e24182e75da56c7f04f683ac3e2c717d8`

อ่าน Storage Rules ที่เผยแพร่กลับมาแล้ว hash ตรงกับไฟล์ที่ทดสอบ (`afccf571f63c4388b34634af92b8e13c6a612e442f22ba314793bb0bd1971bae`) ผลตรวจอยู่ใน `build/media-validation/access-before.json`, `access-after.json` และ `published-rules.json` ไม่มีการเก็บ token ลงรายงาน

กรณีนี้เป็นการแก้ที่เซิร์ฟเวอร์ APK 1.1.3 เดิมใช้ต่อได้ ให้แตะไอคอนรูปเพื่อโหลดใหม่ หรือปิดเปิดแอป เพราะวิดเจ็ตอาจยังเก็บผลโหลดที่ผิดพลาดก่อนแก้ไว้
