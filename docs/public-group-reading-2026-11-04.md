# อ่านกลุ่มสาธารณะก่อนเข้าร่วม

ผู้ใช้ที่เข้าสู่ระบบเปิดหน้ากลุ่มสาธารณะแล้วอ่านโพสต์ รูป วิดีโอ ความคิดเห็น และยอดความรู้สึกได้ทันที ผู้ที่ยังไม่เข้าร่วมไม่มีช่องสร้างโพสต์หรือเขียนความคิดเห็น และปุ่มความรู้สึกถูกปิด การรายงานโพสต์ยังใช้สิทธิ์สมาชิกตามระบบเดิม

กลุ่มส่วนตัวยังคงอ่านได้เฉพาะสมาชิกที่อนุมัติแล้ว เจ้าของ และผู้ดูแลตามสิทธิ์เดิม ผู้ส่งคำขอที่ยังรออนุมัติอ่านไม่ได้ เมื่อออกจากกลุ่มส่วนตัวจะเสียสิทธิ์อ่าน ส่วนการออกจากกลุ่มสาธารณะยังอ่านได้ แต่เขียนไม่ได้

โพสต์ที่แชร์มาจากฟีดยังตรวจสิทธิ์ต้นฉบับตามระบบเดิม การเปิดอ่านกลุ่มสาธารณะไม่ข้ามสิทธิ์ของต้นฉบับที่ถูกจำกัดหรือถูกลบ หากไม่มีสิทธิ์ต้นฉบับ การ์ดแชร์อาจไม่แสดงเนื้อหาส่วนนั้น

## โครงสร้างที่แก้

- `lib/screens/groups/groups_screen.dart`: แยกสิทธิ์อ่านโพสต์ออกจากสถานะสมาชิก และแสดงคำชวนเข้าร่วมเหนือโพสต์แทนการบังโพสต์ทั้งหมด
- `lib/core/widgets/group_post_card.dart`: รับ `canInteract` ปิด reaction/เมนูเขียนสำหรับผู้ชม และเปิดความคิดเห็นเพื่ออ่านได้
- `lib/screens/comments/post_comments_screen.dart`: ซ่อนช่องเขียนจากผู้ชม ฟังสถานะสมาชิกสดเพื่อปิดช่องเขียนเมื่อออกจากกลุ่มในอีกหน้าต่าง
- `lib/core/services/group_service.dart`: บันทึก `groupVisibility` เมื่อสร้าง/แก้โพสต์ โดย Rules ตรวจให้ตรงกับกลุ่มจริง
- `firestore.rules`: อ่านโพสต์/ความคิดเห็น/reaction ตามประเภทกลุ่ม การเขียนยังต้องเป็นสมาชิก
- `storage.rules`: ตรวจโพสต์กับกลุ่มจริงสำหรับสาธารณะ หรือตรวจโพสต์กับสมาชิกสำหรับส่วนตัว โดยไม่เกินสองเอกสาร Firestore ต่อคำขอ
- `functions/index.mjs`: โพสต์แชร์เข้ากลุ่มบันทึกประเภทกลุ่มด้วย และ worker เดิมเติมประเภทกลุ่มให้โพสต์จากแอปรุ่นเก่าในรอบงานถัดไป

## เหตุผลที่มี groupVisibility

Storage Rules อ่าน Firestore ได้ไม่เกินสองเอกสารต่อคำขอ จึงใช้สำเนาประเภทกลุ่มในโพสต์เลือกเส้นทางตรวจสิทธิ์: สาธารณะอ่านโพสต์และกลุ่มจริง ส่วนตัวอ่านโพสต์และสมาชิก การลองตรวจสมาชิกก่อน แล้วตรวจกลุ่มและโพสต์ต่อจะกลายเป็นสามเอกสาร ทำให้รูปของคนนอกกลุ่มโหลดไม่ได้บน Firebase จริง แม้ Emulator อาจผ่าน

สำเนานี้เปิดกลุ่มส่วนตัวเองไม่ได้: Firestore Rules ตรวจค่าจากกลุ่มจริงก่อนบันทึก และ Storage ตรวจกลุ่มจริงซ้ำทุกครั้งที่ใช้เส้นทางสาธารณะ กลุ่มเก่ามีค่าเริ่มต้นแบบจำกัดสิทธิ์จนกว่าจะเติมข้อมูลแล้ว ไม่เปิดสื่อให้คนนอกโดยอาศัยค่าที่หายไป

หน้าแอปปัจจุบันไม่เปลี่ยนประเภทกลุ่มหลังสร้าง หากผู้ดูแลเปลี่ยนผ่าน Admin SDK ต้องปรับสำเนาในโพสต์ด้วย (`syncGroupPostVisibility` หรือ migration) ค่าสาธารณะเก่าจะไม่เปิดสื่อเมื่อกลุ่มจริงเป็นส่วนตัว

## เตรียมข้อมูลเก่า

`tool/backfill_group_post_visibility.mjs` ค่าเริ่มต้นอ่านอย่างเดียว ระบุ `--project=PROJECT_ID` ทุกครั้ง ใช้ `--apply` เมื่อต้องการเติม field จริง สำรองค่าเดิมและเวลาเวอร์ชันข้อมูลใน `build/public-group-access/migration-*.json` ก่อนเริ่มเขียน ใช้ precondition กันเขียนทับโพสต์ที่เปลี่ยนระหว่างตรวจ ไม่เปลี่ยนเนื้อหา createdAt/updatedAt ไฟล์สื่อ หรือสมาชิก รันซ้ำได้โดยข้ามโพสต์ที่ตรงแล้ว

การใช้งานต้องอัปเดตแอปพร้อม Firestore/Storage Rules และ Functions `sharePost`, `tagNotificationWorker` มิฉะนั้น APK เดิมยังบังโพสต์จากผู้ที่ยังไม่เข้ากลุ่ม หรือโพสต์เก่ายังโหลดสื่อไม่ได้สำหรับคนนอก

## ตรวจสอบ

`tool/public_group_access_emulator_test.mjs` ทดสอบ public/private, get/query, รูป/วิดีโอ/thumbnail, สิทธิ์คนรออนุมัติและหลังออกจากกลุ่ม, การปลอมประเภทกลุ่ม, การห้ามคนนอกเขียน และ worker สำหรับโพสต์เก่า รวมใน `tool/run_emulator_tests.mjs` แล้ว ส่วน `tool/group_post_rules_emulator_test.mjs` ปรับผลที่คาดหวังให้คนนอกอ่านกลุ่มสาธารณะได้ และยังทดสอบการเขียน/รายงาน/ลบตามสิทธิ์เดิม

ผลการรันทดสอบและการนำขึ้นระบบเก็บใน `build/public-group-access/` ต้องตรวจการดาวน์โหลดไฟล์จริงด้วยบัญชีที่ไม่ใช่สมาชิกหลังเผยแพร่ เพราะ Emulator ไม่ยืนยันขีดจำกัดการอ่าน Firestore ของ Storage ใน production ได้ครบ

ผลตรวจในเครื่อง: Analyzer ไม่พบปัญหา, Flutter ผ่าน 115 กรณี, Node ผ่าน 32 กรณี, Firebase Emulator ผ่าน 9 ชุดและ integration 36 กรณี ชุดใหม่ครอบคลุมสิทธิ์กลุ่ม 93 เงื่อนไข และตรวจสื่อฟีดตามสิทธิ์เดิมซ้ำอีก 118 เงื่อนไขหลังปรับ Rules ฉบับสุดท้าย Emulator มีคำเตือน expression-limit ใน negative cases บางกรณี จึงไม่ใช้ผล 403 เหล่านี้ยืนยันสาเหตุของการปฏิเสธเพียงอย่างเดียว
