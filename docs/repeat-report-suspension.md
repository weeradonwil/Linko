# พักโพสต์เมื่อมีเคสรายงานซ้ำภายใน 90 วัน

เพิ่มเฉพาะโทษระดับสอง ไม่ใช้ AI และไม่เพิ่มระดับ 7/30 วันหรือหน้าตรวจเคสแอดมินใหม่

## กติกา

- เคสแรกที่ถึงเกณฑ์ยังเตือนและให้แก้ภายใน 24 ชั่วโมงตามเดิม
- เคสใหม่ที่ถึงเกณฑ์ภายใน 90 วันจากเคสล่าสุด พักโพสต์ 72 ชั่วโมงทันที โดยไม่ลบโพสต์จากเงื่อนไขใหม่นี้
- หนึ่งบัญชีรายงานได้หนึ่งครั้งต่อรอบของเนื้อหา เมื่อแก้เนื้อหาจะเปิดรอบใหม่และผู้รายงานเดิมรายงานอีกได้ เมื่อครบเกณฑ์จึงนับเป็นเคสใหม่
- หลายคนรายงานเนื้อหาในรอบเดียวกันไม่ทำให้เป็นหลายความผิด การกดซ้ำ/ส่งพร้อมกันไม่เพิ่มโทษหรือเริ่มเวลาใหม่
- การแก้/ลบโพสต์หรือแจ้งว่าแก้แล้วไม่ล้างประวัติในบัญชีและไม่ปลดเวลาพักที่ลงไปแล้ว
- ถ้าเคสล่าสุดเก่ากว่า 90 วัน จะเริ่มด้วยคำเตือนอีกครั้ง ระบบมีเพียงสองระดับ เคสซ้ำถัดไปยังใช้ 72 ชั่วโมง
- ฟีดใช้เวลาพักบัญชีเดิม ซึ่งบล็อกโพสต์/แชร์เข้าฟีดและกลุ่ม ส่วนรายงานกลุ่มยังให้เจ้าของกลุ่มพิจารณาตามเดิม และพักเฉพาะกลุ่มนั้น ประวัติสองขอบเขตไม่นับรวมกัน
- คงพฤติกรรมเดิมของคำเตือนที่ไม่แก้ภายในกำหนดและการโต้แย้งไว้ ไม่เปลี่ยนไปเป็นระบบแอดมินยืนยันทุกเคส

การนับนี้เป็นกติกาตามรายงาน/การพิจารณากลุ่มเดิม ไม่ใช่การยืนยันความผิดโดย AI

## ข้อมูลและไฟล์สำคัญ

- `functions/repeat_reports.mjs`: คำนวณช่วง 90 วันและเวลา 72 ชั่วโมงจากเวลาเซิร์ฟเวอร์ ไม่ลดระยะพักที่มีอยู่เดิม
- `functions/index.mjs`: แยกรอบรายงาน อ่านและเขียนประวัติพร้อมเวลาพักใน transaction เดียว ใช้ ledger หนึ่งรายการต่อเคส/รอบ
- `functions/policy.mjs`: เพิ่ม `repeatReportSuspensionEnabled` ค่าเริ่มต้นปิด ต้องเปิด `autoEnforce` ด้วยจึงทำงาน
- `lib/screens/profile/moderation_screen.dart`: เพิ่มคำแปลสถานะ `suspended` ว่า "พักสิทธิ์โพสต์ 72 ชั่วโมง" เท่านั้น

ฟิลด์ใหม่:

- `moderation_cases`: `reportRound`, `repeatReportLevel`; ระดับสองใช้ `status:suspended`, `suspensionUntil` และไม่มี deadline ของคำเตือนเดิม
- `account_state/{uid}` / `group_account_state/{groupId}_{uid}`: `lastQualifyingReportAt` และใช้ `postingSuspendedUntil` เดิม
- ใต้ state แต่ละบัญชี: `report_cases/{caseHash}_{round}` เก็บเคสที่นับแล้ว อ่าน/เขียนจาก backend เท่านั้น ไม่ต้องเปิด Rules ให้ client
- เมื่อเปิดฟีเจอร์ รายงาน canonical ใช้ `post_reports/{caseHash}_{round}_{reporterUid}` แทน ID รุ่นเดิมที่รายงานโพสต์เดียวได้ครั้งเดียวตลอด

ข้อมูลเดิมไม่ต้องย้าย และไม่สแกนคำเตือนเก่ามาลงโทษย้อนหลัง เริ่มสะสมจากเคสที่ถึงเกณฑ์หลังเปิดฟีเจอร์ กรณีคำเตือนเดิมยังทำงานตามเดิม

## ตรวจสอบและเปิดใช้

ทดสอบด้วย `functions/test/repeat_reports.test.mjs` และ `tool/repeat_report_emulator_test.mjs` โดยทดสอบ integration เดิมควบคู่กัน ฟีเจอร์ใหม่ต้องตรวจรายงานซ้ำ/พร้อมกัน การแก้โพสต์เดิม ขอบเขต 90 วัน เวลาพัก 72 ชั่วโมง การหมดโทษ การกันแก้ state และการคงสิทธิ์กลุ่มเดิม

ผลตรวจ: Unit Test ผ่าน 40 กรณี รวมกรณีใหม่ 8 กรณี Integration เดิมผ่าน 36 กรณี และฟีเจอร์ใหม่ผ่าน 12 กรณี รวมตรวจ ticket ที่จองก่อนถูกพักว่าใช้ข้ามโทษไม่ได้ แต่ใช้ข้อมูลเดียวกันได้หลังหมดโทษ และไม่คิดบัญชีเดิมซ้ำระหว่างเปลี่ยนรูปแบบรายงาน Analyzer ของหน้าคำเตือนไม่พบปัญหา รัน integration ซ้ำผ่าน `tool/run_repeat_report_tests.mjs` ผลอยู่ใน `build/repeat-report/final-tests.log`

ต้องเผยแพร่เฉพาะ Functions `submitReport`, `legacyReportWorker`, `reviewGroupReport` แล้วจึงเปิด `app_config/moderation.repeatReportSuspensionEnabled:true` โดยเก็บ config อื่นไว้ ค่าเริ่มต้นปิดทำให้ทดสอบ/เผยแพร่โค้ดก่อนเปิดใช้ได้

ย้อนกลับโดยปิด flag เพื่อหยุดการนับ/ลงโทษระดับสองใหม่ เวลาพักที่ลงไปแล้วจะยังมีผลตาม `postingSuspendedUntil` เดิม ไม่ปลดบัญชีทั้งหมดโดยอัตโนมัติ

APK เดิมรับการบล็อกจาก backend และแจ้งเตือนระบุ 72 ชั่วโมงได้อยู่แล้ว ส่วนคำแปลสถานะใหม่จะรวมใน APK ที่สร้างจากโค้ดนี้ ไม่จำเป็นต้องเปลี่ยน Firestore/Storage Rules เพื่อเปิดฟีเจอร์
