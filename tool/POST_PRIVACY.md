# สิทธิ์โปรไฟล์และโพสต์

โปรไฟล์เป็นขอบเขตผู้ชม ส่วนโพสต์เลือกว่าจะเปิดให้ผู้ชมกลุ่มนั้นหรือเห็นคนเดียว ไม่เปลี่ยนค่า `visibility` ของโพสต์เมื่อเปิด/ปิดบัญชีส่วนตัว

| โปรไฟล์ | โพสต์ | เจ้าของ | ผู้ติดตามที่อนุมัติแล้ว | สมาชิกทั่วไป/รออนุมัติ |
|---|---|---|---|---|
| สาธารณะ | สาธารณะ | เห็น | เห็น | เห็น |
| ส่วนตัว | สาธารณะ | เห็น | เห็น | ไม่เห็น |
| แบบใดก็ได้ | เฉพาะฉัน | เห็น | ไม่เห็น | ไม่เห็น |

ตารางนี้อธิบายผู้ใช้ทั่วไปในฟีด/โปรไฟล์ คงสิทธิ์ตรวจสอบเนื้อหาของผู้ดูแลและการซ่อน/บล็อกเดิมไว้

## การเก็บข้อมูล

- `users/{uid}.isPrivate` และสถานะ migration บอกความเป็นส่วนตัวของโปรไฟล์
- `posts/{postId}.visibility` คงค่าเดิม: `public` แสดงคำว่า “สาธารณะ”, `private` แสดงคำว่า “เฉพาะฉัน” ตัวเลือกสาธารณะไม่แสดงคำอธิบายโปรไฟล์ด้านล่าง
- ค่า `followers` รุ่นเก่ารองรับให้อ่านโดยผู้ติดตามที่อนุมัติอยู่แล้ว
- `authorIsPrivate` เป็นสำเนาสถานะโปรไฟล์สำหรับ query ฟีดสาธารณะ งานเปลี่ยนโปรไฟล์อัปเดตเฉพาะสำเนานี้โดยไม่เปลี่ยนสิทธิ์โพสต์
- ยึดเอกสาร `users/{owner}/followers/{viewer}` เป็นหลักฐานการอนุมัติ ไม่ใช้เพียงเอกสาร `following` หรือคำขอที่ยังรออนุมัติ

## ไฟล์สำคัญ

- [`post_service.dart`](../lib/core/services/post_service.dart): รวม query ฟีดสาธารณะ โพสต์ตนเอง และโพสต์ตามสิทธิ์จากบัญชีที่ติดตาม ล้างข้อมูลจาก listener เมื่อเสียสิทธิ์
- [`profile.dart`](../lib/screens/profile/profile.dart): ตรวจสถานะผู้ติดตามก่อนเปิดโพสต์ของโปรไฟล์ส่วนตัว และกรองโพสต์เฉพาะฉันออกจาก query ของผู้ชมอื่น
- [`create_post.dart`](../lib/screens/create_post/create_post.dart): แสดงตัวเลือกสิทธิ์และส่งค่า public/private เดิมลงฐานข้อมูล
- [`post.dart`](../lib/core/models/post.dart): ชื่อสิทธิ์บนการ์ดโพสต์
- [`firestore.rules`](../firestore.rules) / [`storage.rules`](../storage.rules): บังคับสิทธิ์ที่ฐานข้อมูลและไฟล์สื่อ แม้เรียก API โดยตรง
- [`firestore.indexes.json`](../firestore.indexes.json): index userId/visibility/createdAt รองรับ query ผู้ติดตามโดยไม่บังคับ authorIsPrivate=false
- [`post_access.mjs`](../functions/post_access.mjs) / [`index.mjs`](../functions/index.mjs): สิทธิ์รายงานและแจ้งเตือนแท็กตรงกับโพสต์ ผู้ที่เปิดโพสต์ไม่ได้จะไม่ได้รับแจ้งเตือนที่เปิดใช้ไม่ได้

การแชร์คงข้อกำหนดเดิม: ผู้ติดตามไม่มีสิทธิ์นำโพสต์ของบัญชีส่วนตัวไปแชร์ต่อ เจ้าของยังเลือกแชร์โพสต์ทั่วไปของตนเข้าแชทหรือกลุ่มได้ และผู้รับต้องผ่านสิทธิ์ปลายทาง/รายการแชร์ ส่วนโพสต์เฉพาะฉันแชร์ไม่ได้

## การตรวจสอบ

รันทดสอบ Flutter และ backend:

```powershell
flutter test --no-pub --reporter expanded
node --test --test-isolation=none "functions/test/*.test.mjs"
```

รันสิทธิ์จริงบน Emulator โดยใช้ demo project เท่านั้น ต้องติดตั้ง dependencies ตาม lockfile ใน `functions` และมี Java 21 ใน PATH:

```powershell
firebase emulators:exec --config firebase.emulator.test.json --project demo-linko --only auth,firestore,storage,functions "node tool/run_post_privacy_tests.mjs"
```

ชุดทดสอบประกอบด้วย:

1. เมทริกซ์อ่าน document และดาวน์โหลดไฟล์รูป/วิดีโอตาม MIME type ของ fixture ทั้งสองโหมดโปรไฟล์ การอนุมัติ ยกเลิกสิทธิ์ และ query ที่พยายามอ่านโพสต์เฉพาะฉัน ไม่ได้ตรวจการ render หรือถอดรหัสวิดีโอ
2. เปลี่ยนความเป็นส่วนตัวของโพสต์ 501 รายการผ่าน cursor และงาน migration ที่ทำต่อได้
3. Query รวมผู้เขียนส่วนตัวห้าคน ทั้ง `public` และ `followers` โดยไม่เปิด `private` รวมการอ่านโพสต์เก่าแบบแบ่งหน้า
4. Functions และ Rules ของการแท็ก แจ้งเตือน รายงาน และแชร์ รวมกรณีผู้ติดตามที่อนุมัติกับบัญชีที่ยังไม่ได้อนุมัติ

การติดตั้งใช้งานต้องนำ Rules, index ใหม่ และ Functions ที่เกี่ยวข้องขึ้น Firebase ด้วย โค้ด Flutter ใช้ `lib/main.dart` ตามปกติ

## ผลตรวจและเผยแพร่ 4 พฤศจิกายน 2026

- Flutter ผ่าน 109/109 รวมกรณีเลือก “เฉพาะฉัน” บนจอ 320 พิกเซลและยืนยันว่าบันทึกเป็น `private`
- Node backend ผ่าน 32/32 รวมเมทริกซ์โปรไฟล์/โพสต์/ผู้ติดตามและช่วงเปลี่ยนสถานะโปรไฟล์
- Emulator ผ่านทั้ง 4 ชุด: สิทธิ์ document/ดาวน์โหลดสื่อ/query 118 เงื่อนไข, migration 501 โพสต์, query ผู้เขียน 5 คนและแบ่งหน้า 61 โพสต์, integration ของ Functions 36 กรณี
- กรณีใหม่ของ Functions ยืนยันว่าผู้ติดตามที่อนุมัติได้รับแจ้งเตือนแท็กและรายงานโพสต์ได้ ส่วนคนที่ยังไม่อนุมัติไม่มีสิทธิ์ ผู้ติดตามแชร์โพสต์จากบัญชีส่วนตัวต่อไปฟีดไม่ได้
- Analyzer ของไฟล์ Dart ที่แก้ทั้ง 6 ไฟล์ไม่พบปัญหา และตรวจ syntax JavaScript/รูปแบบไฟล์ผ่าน
- สำรอง Rules จริงก่อนเปลี่ยน และยืนยันว่าตรงกับโค้ดตั้งต้น จากนั้นเผยแพร่ Firestore/Storage Rules, indexes และเฉพาะ `submitReport`, `legacyReportWorker`, `sharePost`, `tagNotificationWorker`
- อ่านกลับหลังเผยแพร่เวลา 08:31 น. (Asia/Bangkok): hash ของ Rules ตรงกับไฟล์ที่ทดสอบ, index ใหม่เป็น `READY`, Functions ทั้ง 4 ตัวเป็น `ACTIVE` บน Node.js 22 ไม่มีการลบ indexes อีก 2 ตัวที่มีอยู่บน Firebase
- ผลทดสอบและข้อมูลเผยแพร่อยู่ใน `build/privacy-validation/` ซึ่งไม่เก็บเข้า Git; Emulator ปิดแล้ว ไม่มีการสร้างบัญชีหรือโพสต์ทดสอบใน production

ข้อจำกัด: integration ใช้ Emulator บน Node.js 26 ตามเครื่องนี้ ส่วน production ใช้ Node.js 22; ยังไม่ได้เปิดแอปสองบัญชีจริงหรือทดสอบการ render รูป/วิดีโอผ่านหน้าจอ ชุดทดสอบยืนยันการดาวน์โหลดไบต์ fixture ผ่าน Rules เท่านั้น Emulator ส่งรายละเอียด `evaluation error`/expression limit ในบางกรณีที่ตั้งใจให้ถูกปฏิเสธ จึงใช้ทั้งกรณีอนุญาตและปฏิเสธประกอบกัน ไม่ใช้ HTTP 403 อย่างเดียวเป็นหลักฐานแยกเงื่อนไขภายใน Rules

การตรวจภายหลังพบ Storage Rules อ่าน Firestore เกินเพดานสองเอกสารในเส้นทางผู้ชมทั่วไป ทำให้รูปโพสต์สาธารณะได้ HTTP 403 แม้โพสต์อ่านได้ แก้ให้ตรวจเส้นทางสาธารณะก่อน ทดสอบ 118 เงื่อนไขผ่าน และเผยแพร่เฉพาะ Storage Rules หลังผู้ใช้อนุญาตแล้ว โหลดรูปเดิมจาก Firebase จริงได้ HTTP 200 ครบ 169,182 ไบต์ พร้อมยืนยัน hash ของ Rules ที่เผยแพร่ตรงกับไฟล์ ดู [รายงานรูปโพสต์](../docs/feed-media-rules-fix-2026-11-04.md)
